Family Bot for Discord

Что делает бот:
- показывает панель семьи по ролям
- считает активность участников
- принимает заявки в семью
- даёт выговоры и похвалы
- поддерживает ручные ранги, авто-ранги и защитные функции
- умеет отвечать через DeepSeek API, а без ключа автоматически использует локальный режим
- разбирает вопросы по законодательству Majestic RP через `/law question:<ситуация>` и прикладывает ссылки на найденные нормы
- создаёт приватные обращения поддержки через `/ticket` с логами, transcript и системой прав
- хранит setup и подписки серверов в JSON-базе без SQL

Быстрый старт:
1. Установи зависимости:
   `npm install`
2. Скопируй шаблон окружения:
   `.env.example` -> `.env`
3. Заполни минимум эти переменные:
   `TOKEN`, `GUILD_ID`, `CHANNEL_ID`
4. Укажи роли семьи:
   `ROLE_LEADER`, `ROLE_DEPUTY`, `ROLE_ELDER`, `ROLE_MEMBER`, `ROLE_NEWBIE`
5. Чтобы включить AI-помощника, укажи:
   `AI_ENABLED=true`
   `DEEPSEEK_API_KEY=...` (необязательно; задаётся только в Railway Variables или локальном `.env`)
6. Если хочешь owner-доступ к тарифам, укажи:
   `BOT_OWNER_IDS=твой_discord_id`
7. Для Railway лучше укажи пути к постоянным файлам:
   `DATABASE_FILE=/data/database.json`
   `STORAGE_FILE=/data/storage.json`

Support tickets:
- `TICKET_CATEGORY_ID` — категория приватных тикетов
- `TICKET_SUPPORT_ROLE_ID` — роль поддержки
- `TICKET_LOG_CHANNEL_ID` — канал логов (необязательно)
- `TICKET_PANEL_CHANNEL_ID` — канал панели (необязательно; иначе текущий канал)
- `TICKET_PING_SUPPORT=true`
- `TICKET_COOLDOWN_SECONDS=60`
- `TICKET_MAX_OPEN_PER_USER=1`
- `TICKET_DELETE_DELAY_SECONDS=5`

Команды: `/ticket setup`, `/ticket info`, `/ticket close`, `/ticket claim`, `/ticket add`, `/ticket remove`, `/ticket list`.
8. Если нужен AI-анализ заявок, задай:
   `ACCESS_APPLICATIONS`
9. Для Telegram-моста укажи:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`
   Опционально: `TELEGRAM_ANNOUNCEMENTS_CHAT_ID`, `DISCORD_ANNOUNCEMENTS_CHANNEL_ID`, `DISCORD_ANNOUNCER_ROLE_IDS`
10. Запусти проверки:
   `npm run check`
11. Запусти бота:
   `npm start`

Что проверяется на старте:
- обязательные переменные `TOKEN`, `GUILD_ID`, `CHANNEL_ID`
- корректность Discord ID в каналах и ролях
- настройки авто-рангов и прав доступа
- мягкие предупреждения для необязательных настроек и fallback-поведения

Полезные команды:
- `npm test` - smoke-тесты заявок, embed'ов и рангов
- `npm run check` - синтаксис + smoke-тесты
- `npm start` - запуск бота
- `/setup` - сохранить настройки сервера в JSON-базе
- `/adminpanel` - встроенная админка сервера в Discord
- `/subscription` - owner-команда для смены `free/premium`
- `/help` - показать доступные команды по тарифу сервера
- `/debugconfig` - безопасная сводка конфигурации для админов без секретов
- `/announce text:...` - отправить семейное объявление из Discord в Telegram
- `/event text:...` - отправить семейное событие из Discord в Telegram
- `/close reason:...` - закрыть текущий ticket

Telegram-команды:
- `/reply <ticketId> <text>` - ответить из Telegram в Discord ticket
- `/announce <text>` - отправить объявление из Telegram в Discord
- `/event <text>` - отправить событие из Telegram в Discord

Как это работает:
- Бот использует `storage.json` для текущей игровой активности и `database.json` для мульти-серверных setup/подписок.
- На `free` доступны базовые команды семьи и одна серверная конфигурация.
- На `premium` включаются premium-функции: локальный AI, авто-ранги и логи.
- `/setup` сохраняет сервер в JSON-базу, `/adminpanel` показывает текущий тариф и настройки, `/help` показывает команды по текущему плану.
- Для Railway нужен persistent volume или путь вроде `/data/database.json`, иначе JSON-файлы будут теряться после redeploy/restart.

Основные файлы:
- `src-ts/index.ts` - запуск и wiring
- `src-ts/copy.ts` - все пользовательские тексты
- `src-ts/database.ts` - JSON-база setup и подписок
- `src-ts/applications.ts` - сценарии заявок
- `src-ts/embeds.ts` - embeds, кнопки, модалки и диагностические карточки
- `src-ts/storage.ts` - локальное хранилище
- `src-ts/ai.ts` - AI и локальный запасной ответ
- `src-ts/commands.ts` - регистрация slash-команд

Проверки и деплой (1.3.0):
- Нужен Node.js 22 или новее; Docker запускается на Node.js 24.
- Перед пушем: `npm run check`. CI проверяет Node.js 22/24 и сборку Docker.
- Docker также выполняет весь `npm run check`: неуспешные тесты блокируют сборку образа.
- В Railway выбери Dockerfile и Start Command `npm run start:ts` (или оставь команду Docker по умолчанию).
- В Railway Deploy укажи Healthcheck Path `/healthz`, таймаут 300 секунд. Бот слушает предоставленный `PORT`.
- `/healthz` возвращает 200 только при подключении к Discord и доступном хранилище; иначе 503. Секреты и пути не публикуются.
- Healthcheck проверяет запуск деплоя, а не непрерывно следит за сервисом. `/health` в Discord остаётся расширенной диагностикой.
- Для ожидания результатов GitHub Actions перед деплоем включи Wait for CI в Railway, если этот параметр доступен в подключённом сервисе.
- До подтверждения массовые ЛС/упоминания не отправляются. Код действует 2 минуты и привязан к инициатору и каналу.
- Подтверждения переживают рестарт до истечения двух минут. Автоматической рассылки после рестарта нет: подтвердите действующий код или повторите запрос.
- Журнал массовых действий хранится рядом с DATA_FILE в файле <DATA_FILE>.actions.json на постоянном томе. Статусы получателей: sending (результат неизвестен после сбоя), delivered, failed. История хранится 30 дней. Доставленные и неопределённые отправки пропускаются при повторном запросе в течение 24 часов; это относится и к ЛС, и к упоминаниям.
- Ограничение в 24 часа считается отдельно по каждому получателю. Сетевой таймаут сохраняется как неизвестный результат, а не подтверждённая недоставка. Неопределённые отправки автоматически не повторяются в этот период.
- Журнал проверяет структуру JSON и сохраняет атомарную резервную копию .bak. При восстановлении из копии подтверждения сбрасываются, отправки приостанавливаются на 24 часа, чтобы не повторить потерянную последнюю доставку. Если обе копии повреждены, обычная работа продолжается, массовые действия заблокированы до восстановления файла и перезапуска.
- Необработанные исключения и отклонения Promise запускают сохранение и остановку с кодом 1. Ошибки отложенных команд завершают ответ сообщением о сбое.
- Основное хранилище и база настроек атомарно заменяют и основной файл, и .bak через временные файлы с синхронизацией записи. /healthz и /health отдельно проверяют хранилище, базу настроек и журнал действий.
- При загрузке проверяется структура коллекций, записей и настроек; отсутствующие поля старых форматов дополняются стандартными значениями. Непригодные файлы сохраняются рядом как .corrupt-<дата>-<ID>. Если обе копии непригодны, запуск останавливается до восстановления, чтобы пустая база не затёрла данные. Архивы исключены из Git и Docker.
- Автоматическая карточка обновления отправляется только для коммита, начинающегося с Release, если для версии заполнены release-notes.ts. Фиксы с сообщением Fix карточку не отправляют. Уже объявленная версия повторно не публикуется при новом коммите; для следующего крупного объявления увеличьте версию и заполните заметки.
- Мут и снятие мута проверяют свежие данные инициатора и цели, право администратора, иерархию ролей и доступность модерации; при отказе действие записывается в журнал как failed.
- Во время массовых ЛС права инициатора проверяются перед каждым получателем, во время упоминаний перед каждой партией. Запрос с упоминанием бота «отмени рассылку» отменяет дальнейшие отправки; текущая отправка может завершиться. Отменять может инициатор или администратор.
- При SIGTERM/SIGINT бот прекращает принимать новую работу, ждёт текущие обработчики и фоновые операции до 20 секунд, сохраняет данные и закрывает соединения. Общий предел остановки 25 секунд. При превышении лимита проверьте журнал прерванных действий.
- Проверка хранилища выполняет пробную запись и переименование отдельного файла раз в 10 секунд, не изменяя пользовательские данные.
- Пользовательские данные JSON, браузерные профили и `.env` не включаются в Docker-образ. Храни их на persistent volume.
- Рабочие модули используют типизированные импорты, но полное устранение оставшихся `any` в старых обработчиках ещё не завершено.
- interaction-runtime.ts типизирован без явных any: команды, кнопки, формы и зависимости используют проверяемые контракты.


Администрирование и восстановление (1.7.0)
- /settings show — каналы, роли и модули; /settings check — проверка выбранных объектов по кешу Discord без сканирования сообщений.
- /settings channel key value, /settings role key value, /settings module key enabled — изменение через существующие обработчики; канал должен быть текстовым, доступным боту с View Channel, Send Messages и Embed Links.
- /settings history — последние изменения, автор, время, статус и значения до/после. /settings undo id — откат настроек или ручного изменения ранга из журнала; требуется действующий Administrator. Если состояние после изменения уже изменено, откат блокируется.
- Журнал <DATA_FILE>.admin-changes.json и его .bak должны находиться на постоянном томе. Запись намерения выполняется до изменения. После перезапуска running/reverting помечаются interrupted; их результат нужно проверить вручную. Восстановленная устаревшая .bak не даёт права на автоматический откат. Автоматического повторного выполнения нет.
- Журнал охватывает /setrole, /setchannel, /setmode, /setmodule, /setpanelroles, /setfamilytitle, /setart, изменение оформления через /cardstyle и ручные кнопки ранга. История ограничена 1000 записями; интерфейс показывает последние 20.
- Откат ранга проверяет текущие права, иерархию и безопасность изменяемых ролей; возвращаются только изменённые роли. Автоматические назначения рангов, баны, кики и отправленные сообщения этим откатом не отменяются.
- /health показывает очередь и нагрузку Discord, паузы, ошибки авторизации и журнал доставок, включая неопределённый результат после остановки. Длинный отчёт разбивается на приватные сообщения.
- /serverbackup verify backup_id читает backup из GitHub и запускает алгоритм восстановления в отдельных коллекциях в памяти. Проверяются формат, IDs, категории, права и создание модели ролей/каналов. Это проверка структуры и алгоритма, а не прав бота в Discord или восстановления пользовательских сообщений и локальной базы.
- /serverbackup restore сохраняет действующие объекты; уже восстановленные роли и каналы используются повторно. При нескольких совпадающих каналах восстановление останавливается: перед повтором проверьте результат. Если не удалось обновить список ролей/каналов, создание backup прекращается, чтобы не сохранить неполный снимок.
- Предпросмотр неактивных показывает исключения по голосу, отпуску, активности и недостаточному сроку наблюдения; основание решения выводится по данным бота.


Рабочие данные, ИИ и очередь обращений (1.8.0)
- До загрузки проверяется версия базы настроек (поддерживается meta.version=1); по возможности создаётся предстартовый снимок. Повреждённый основной JSON по-прежнему проходит штатное восстановление из .bak; новый код не заменяет его пустой базой.
- Каждые 6 часов после flush создаётся локальный архив storage/database и существующих журналов actions/admin-changes/discord-rate-limit/ai-usage. DATA_BACKUP_DIR задаёт папку; DATA_BACKUP_RETAIN (минимум 2, по умолчанию 14) задаёт число архивов. Архивы содержат персональные данные: храните на приватном постоянном томе. Это не удалённая копия и не защита от потери диска. .env и сессии браузера в архив не включаются.
- После npm run build:ts: npm run data:maintenance -- create --offline (бот должен быть остановлен); verify АРХИВ; restore-test АРХИВ --destination НОВАЯ_ПАПКА. Тест восстановления проверяет хеши и читает восстановленные файлы в отдельной новой папке; рабочие файлы не заменяет. preflight проверяет версию базы и создаёт архив. Путь рабочих файлов берётся из STORAGE_FILE/DATABASE_FILE с теми же значениями по умолчанию, что и запуск бота.
- AI_DAILY_TOKENS=200000 ограничивает дневной расход обоих провайдерных интерфейсов (общий чат и игровой юридический помощник). AI_USER_DAILY_REQUESTS=50 и AI_CHANNEL_DAILY_REQUESTS=200 действуют для запросов с контекстом события Discord; фоновые задачи ограничены общим бюджетом. День — Europe/Bucharest. Токены не являются точной денежной стоимостью.
- До запроса резервируются UTF-8 байты сообщений + максимальный ответ. При наличии usage.total_tokens резерв уточняется. Неизвестный результат сохраняет консервативный резерв. Журнал .ai-usage.json должен находиться на постоянном томе; повреждение или утрата основного файла при наличии .bak блокирует запросы до проверки журнала. При 80% резерва предупреждение в доступные каналы logs отмечается до отправки; результат неизвестен — автоматического повтора нет. /health показывает бюджет. При запуске через ai:eval оценка также использует этот журнал; не запускайте её одновременно с рабочим ботом.
- Пользовательские события получают более высокий приоритет в REST-очереди, чем фоновые задачи. Через каждые 2 секунды ожидания фоновые задачи повышают приоритет; ограничения скорости, числа запросов и отмена сохраняются.
- AI_HISTORY_MINUTES=15 задаёт срок временной памяти диалога (не менее 1 минуты), память сбрасывается при перезапуске. CLOSED_RECORD_RETENTION_DAYS=180 задаёт хранение закрытых заявок/тикетов от reviewedAt/closedAt. Активные дела, ожидающие доставки и записи без даты решения сохраняются. Модерационные доказательства, чёрный список, журналы действий, файлы Discord и локальные архивы этой очисткой не удаляются.
- Для офлайн-удаления закрытых обращений/черновиков участника: npm run data:maintenance -- forget --offline --guild GUILD_ID --user USER_ID --confirm USER_ID. Сначала создаётся backup. Это удаление закрытых персональных обращений, а не полное удаление всех данных: активные обращения, модерация и резервные копии сохраняются. Остановите бот, чтобы не перезаписать изменения живым хранилищем.
- /workqueue show показывает заявки pending и открытые тикеты старше суток, ответственного, срок ожидания и следующий шаг. /workqueue remind — явная команда администратора для напоминания в настроенный канал logs. На обращение допускается одна попытка; она сохраняется до отправки. Упоминания отключены. Автоматического расписания напоминаний нет.
- npm run ai:eval без --live показывает число обезличенных сценариев. npm run ai:eval -- --live выполняет запросы к настроенной модели и выводит ответы с критериями ручной оценки. Обычные тесты проверяют передачу контекста и маршрутизацию с заглушкой, а не семантическое качество живой модели. Реальные переписки не собираются.
- Ошибки основных обработчиков событий и взаимодействий пишут имя/код/HTTP-статус вместо тела запроса Discord; отдельные модульные логи и журнал модерации имеют собственные правила хранения.


Музыка (1.9.0)
1. Нужны Node.js >=22.12.0, FFmpeg, yt-dlp с дополнительными зависимостями по умолчанию (yt-dlp[default]). Dockerfile и nixpacks.toml устанавливают инструменты. Локально установите их отдельно и при необходимости задайте абсолютные пути FFMPEG_PATH и YTDLP_PATH. /music status проверяет доступность инструментов без поиска и подключения к голосу.
2. Администратор включает модуль: /settings module key:music enabled:true. По умолчанию music выключен. Зайдите в обычный голосовой канал. Боту нужны View Channel, Connect и Speak. Stage-каналы не поддерживаются.
3. /music play query:Кино — Группа крови — поиск первого результата YouTube без ссылки. Поиск выполняется при запуске трека, результат показывается в текстовом канале. Можно также передать YouTube-ссылку, публичную прямую HTTPS-аудиоссылку/радиопоток либо file с MP3/OGG/Opus/WAV/FLAC/M4A/AAC/WebM. Передавайте либо query, либо file. Сообщения без slash-команды не запускают музыку.
4. /music queue, pause, resume, skip, stop. Пропуск отменяет и поиск, и загрузку; stop очищает очередь и отключает бота. Управление — из того же голосового канала, с Administrator или ролью из MUSIC_DJ_ROLE_IDS. Добавлять треки в занятую сессию можно только из её канала; администратор не переносит чужую сессию командой play.
5. До 25 ожидающих треков на сервер, до 5 треков участника с текущим, до 3 активных серверов. Поиск — до 20 секунд, загрузка заголовков — 15 секунд, простаивающий поток — 20 секунд, трек целиком — 15 минут/100 МБ. Длинные записи и live-результаты поиска не принимаются; прямой радиопоток также ограничен временем. Недоступный трек пропускается. Очередь живёт в памяти и не запускается заново после рестарта.
6. Нет гарантии доступности любой песни: приватные, платные, DRM-защищённые, регионально недоступные записи, плейлисты и страницы Spotify/Apple Music не являются поддерживаемыми источниками. Обход ограничений/вход с cookie не предусмотрен. Доступность YouTube зависит от сети хостинга и актуальности yt-dlp. Уточняйте исполнителя при неправильном первом результате.
7. Потоки загружаются через публичные HTTPS-адреса с проверкой DNS и каждого редиректа; FFmpeg получает данные через pipe без сетевого доступа. Загрузки не сохраняются на диск. При уходе последнего человека, удалении канала, отключении music и завершении процесса очереди/потоки/подпроцессы и voice-соединения освобождаются.
8. Voice Rooms используют атомарное сохранение и .bak. Если обе копии повреждены, требуется восстановить данные; пустое хранилище поверх них не записывается. Файл VOICE_ROOMS_DATA_FILE включён в архивы рабочих данных и должен лежать на постоянном томе. Боты не считаются слушателями при очистке комнат. Если Discord отказал в удалении, запись сохраняется.
9. Локальные тесты проверяют очередь, отмену и изоляцию, поиск с заглушкой yt-dlp, роли, исключение приватных IP и реальное кодирование Opus. Они не подтверждают воспроизведение в живом Discord. После развёртывания проверьте /music status и один короткий трек в отдельном голосовом канале.
Документация используемых компонентов: https://discord.js.org/docs/packages/voice/0.19.2 и https://github.com/yt-dlp/yt-dlp.
