# Аудит family-bot — 28 октября 2026

Проверены точки входа npm/Docker/CI, конфигурация TypeScript, импорты рабочего кода, каталог 73 команд и ссылки на их обработчики. Дополнительно просмотрены обработчики событий/взаимодействий, заявки, ранги, модерация, Telegram/объявления, тикеты, хранилища, очередь Discord, резервные копии и внешние клиенты ИИ/Majestic. Прогон тестов выполняется на заглушках и временных данных, без запуска рабочего клиента.

## Исправленные проблемы

- Docker-контекст не исключал новые журналы admin-changes/ai-usage и папку data-backups: локальные данные могли попасть в собираемый образ.
- Схема бюджета ИИ допускала массив вместо словаря счётчиков: свойства пользователя такого массива теряются при JSON-сериализации. Теперь структура и числовые значения проверяются; некорректный журнал блокирует передачу запросов.
- `/health` после полуночи показывал расход предыдущего дня до первого запроса. Отображение нового дня исправлено без сброса/записи журнала при чтении диагностики.
- Предстартовый архив включал только storage/database, тогда как штатный и ручной включали также журналы. Состав источников унифицирован.
- Проверка версии базы выполнялась для основного пути запуска, но не внутри createDatabase и не для .bak. Теперь загрузка базы, включая резервную, отвергает неподдерживаемую версию до нормализации и перезаписи.
- Ошибка таймера отложенной записи database могла стать необработанным исключением. Теперь она регистрируется, а health сохраняет признак ошибки; явный flush по-прежнему выбрасывает исключение вызывающему коду.
- Таймаут юридического ИИ заканчивался на получении HTTP-заголовков. Чтение JSON также ограничено сроком.
- У клиента Majestic API не было общего таймаута HTTP/JSON; текст ошибки включал сырой ответ сервера. Добавлен таймаут, сырое тело исключено из сообщения ошибки.
- При ручном изменении ранга проверялась свежая версия GuildMember, а операция и снимок могли использовать старую. Операция использует полученный свежий объект. Если роль не найдена/недоступна в реальном guild, назначение блокируется до изменений ролей.
- Часть ошибок журнала отката была обычными Error, а интерфейс выводил только AdminChangeError: причина терялась. Ошибки журнала унифицированы; перед записью отката настроек повторно проверяется отсутствие изменений во время проверки объектов.
- Проверка синтаксиса держала вручную перечисленные JS-файлы. Теперь рекурсивно проверяются dist-ts, scripts и tests, включая новые служебные команды.
- Удалён пустой корневой файл src — неиспользуемый остаток переезда.

## Что подтвердилось по переезду

Рабочая точка входа — dist-ts/index.js; TypeScript не импортирует удалённые корневые JS-обёртки; allowJs выключен; @ts-nocheck не используется. JSON правовой базы импортируется из src-ts/data и участвует в компиляции. Наличие строк с именами команд проверяет связность каталога, но не заменяет проверки поведения каждого сценария.

## Оставшиеся недоработки

1. **Частичная доставка объявлений Discord/Telegram.** В announcements запись сохраняется после отправок; общего постоянного журнала намерений для обеих платформ нет. После неоднозначного сетевого результата ручной повтор может продублировать одну из доставок. Нужен отдельный статус по платформам и правило работы с неизвестным результатом.
2. **Полнота отката.** Журнал покрывает основные slash-настройки и ручные кнопки ранга. Изменения из всех остальных модулей, автоматические ранги и внешние изменения Discord не входят в единый откат.
3. **Типизация.** В крупных index/command-runtime/types остаются многочисленные any. strict-компиляция проходит, но не доказывает корректность всех объектов discord.js в этих участках.
4. **Majestic rate limiter.** Его собственная очередь не имеет ограничения длины или отмены ожидания. Таймаут нового HTTP-клиента начинается после допуска очередью. При всплеске запросов ожидание может быть долгим; это отдельный оставшийся риск.
5. **Резервные копии.** Локальные архивы не защищают от потери тома; проверка хеша не является аутентификацией от намеренной подмены; данные не шифруются. Тестовое восстановление не заменяет запуск отдельного экземпляра бота с восстановленным состоянием.
6. **Внешняя проверка.** Не выполнялись Docker-сборка, реальные обращения Discord/Telegram/Majestic и платные запросы модели. Качество диалогов реальной модели требует отдельной оценки.

Для этого набора подготовлена карточка исправлений 1.8.1. Отдельные архитектурные риски выше не объявляются исправленными.
